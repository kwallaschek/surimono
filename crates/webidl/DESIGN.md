# surimono-webidl: design notes

Phase-2 scaffolding (P1-DOM-01). Internal crate, `publish = false`; nothing here
reaches the `surimono` facade before checkpoint 3.

## Pipeline

```
idl/*.idl (webref ed/idl, pinned) ── parse ──▶ ast ── IdlSet (merge partials, mixins)
                                                         │
                                         generate_stubs(STUB_INTERFACES)
                                                         ▼
                                     src/stubs.rs (checked in, test keeps it fresh)
```

- **Vendored, not fetched.** `idl/` holds the webref files at the commit in
  `src/vendored.rs`; `fetch-webref.sh` refreshes them by hand. Licences:
  `idl/SOURCES.md`.
- **Own parser.** `weedle2` 5.0.0 was tried first: it fails on the current
  webref IDL and calls `assert!` when input is left over, so bad input panics.
  The hand parser (`src/lexer.rs`, `src/parser.rs`, about 900 lines) follows the
  WebIDL grammar, returns `ParseError { line, column }` for any bad input, caps
  nesting at 64, and has no dependencies.
- **Checked-in output.** `src/stubs.rs` is generated by
  `cargo run -p surimono-webidl --example regen`, not by `build.rs`: the diff
  is reviewable, builds don't run the generator, and `tests/codegen.rs` fails
  if the file is stale. Same for `tests/golden/mini.rs` (from a small
  hand-written IDL file that covers every member kind).
- **Deterministic.** `IdlSet` sorts files by name, so input order doesn't
  matter; merge order is the main definition, then partials, then mixins by
  `includes` position; the generator uses no hash maps, timestamps or paths.

## Ids, not pointers

JS never holds a Rust pointer and Rust never holds a pointer into JS state
that JS can reach back through:

- Every platform object is an `ObjectId(u64)` (planned: 32-bit slot plus
  32-bit generation, so a reused slot can't be confused with a stale id).
  The host (`surimono-dom`) owns the tables: blitz-dom node ids for nodes,
  its own arenas for `DOMTokenList`, events, ranges and the like.
- Generated methods take `this: ObjectId` and return ids. A forged or stale id
  is a `BindingError` (a JS `TypeError`), never undefined behaviour.
- One wrapper per id, so `a.firstChild === a.firstChild` and expandos stick:
  the host keeps a per-document table `ObjectId → wrapper` (strong
  `rquickjs::Persistent`). Wrappers hold only their id, so there is no cycle
  through Rust; the table is dropped with the document, before the runtime.
  The soak test must stay flat. (P1-DOM-02 checks this with a leak test.)
- Open for P1-DOM-02: when blitz-dom may free a detached node that a wrapper
  still names (JS can re-insert it). Likely answer: detached nodes stay until
  the document is dropped; per-render documents make that bounded.

## rquickjs class shape (phase 2)

One Rust class for all platform objects, not one class per interface:

```rust
#[derive(Trace, JsLifetime)]
#[rquickjs::class]
struct PlatformObject {
    #[qjs(skip_trace)] id: ObjectId,
    #[qjs(skip_trace)] interface: u16, // index into stubs::INTERFACES
}
```

- At context setup, for each `InterfaceInfo` (parents first) the binding layer
  builds the interface object and its prototype, links the prototype to the
  parent's (`Node.prototype → EventTarget.prototype`), and defines each
  member: accessors for attributes, functions for operations, constants on
  both the interface object and the prototype.
- Each native function unwraps `this` to `PlatformObject`, checks that its
  `interface` inherits from the member's interface (the brand check; otherwise
  `TypeError: Illegal invocation`), converts arguments by the WebIDL
  ECMAScript rules, calls the host's trait method and converts the result.
- The host implements the generated traits (`impl Node for DomHost`). Default
  bodies return `NotImplemented`, so members land one at a time; WPT tells us
  which ones matter.

## What the generator will grow next (E2-01)

- Argument conversion glue per member (overload resolution by argument count
  and type, `[LegacyNullToEmptyString]`, `[EnforceRange]`, defaults from IDL
  rather than `Option`).
- Precise types for dictionaries and enums (today `Value` and `String`), and
  pair iterators, `maplike` and `setlike` (today listed as not generated).
- `[Exposed]` filtering for members from partials and mixins, `[SameObject]`
  and `[NewObject]` handled by the wrapper table, `[CEReactions]` ignored
  (no custom elements beyond the basics).
- Rust-side name clashes across the trait hierarchy (`append` on both
  `Element` and `Document`, from `ParentNode`) are legal Rust but call sites
  must name the trait; the binding layer always does.
