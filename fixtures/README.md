# Fixtures

Outside truth for surimono. Every expectation here comes from Chrome, a spec
or WPT, never from surimono's own output. Owned by the conformance researcher.

| Folder | What |
|---|---|
| `fonts/` | The pinned test fonts (Noto Sans, Noto Sans JP), used by Chrome and by surimono/fulgur alike. `fonts.toml` pins each file. |
| `islands/<name>/` | Visual fixtures for phase 1: a page with chart islands, plus its Chrome references. |
| `tools/` | The Chrome reference pipeline, the comparison tool and the fixture generator (Node, pinned by `package-lock.json`). |

## Island fixture format

```
fixtures/islands/<name>/
  input.html            the document (generated by tools/gen-islands.mjs from tools/defs/islands.mjs)
  meta.toml             title, renderer, library version, fonts, page size, what it tests
  reference/
    chrome-<page>.png   the whole page printed by Chrome, 96 dpi
    island-<i>.png      island i alone, printed by Chrome on a page of exactly its size, 96 dpi
    reference.toml      Chromium, Playwright, poppler and library versions; size and sha256 of each PNG
```

`input.html` is a complete document: `@font-face` rules pointing at
`../../fonts/`, an explicit `@page { size: 210mm 297mm; margin: 15mm }`, and one
or more island markers, each inside `<figure class="island">` with
`figure.island > svg { display: block }` so the inlined SVG lays out the same
way in every engine. The page is a realistic report (header, intro, figure,
caption, summary rows) built only from layout that fulgur and Chrome agree on
(see "Diff metric"):

```html
<script type="application/vnd.surimono+json" data-renderer="echarts|vega-lite|vega"
        data-width="W" data-height="H">{spec JSON}</script>
```

The JSON escapes `<`, `>` and `&` as `<`, `>`, `&`, so it can
never close its `<script>`.

### Island contract (what Chrome does, so what surimono must match)

- **echarts**: `echarts.init(null, null, { renderer: "svg", ssr: true, width: W, height: H })`,
  `setOption({ ...spec, animation: false })`, `renderToSVGString()`.
- **vega-lite**: `vegaLite.compile(spec).spec`, then as vega.
- **vega**: `new vega.View(vega.parse(spec), { renderer: "none" })`, `runAsync()`, `toSVG()`.
  The spec is used as is. Fixtures set `width`, `height` and
  `autosize: { type: "fit", contains: "padding" }` so the SVG is exactly W×H; the
  harness fails if it isn't.
- Each marker is replaced by the SVG string; nothing else in the document changes.
- Text is measured with the page's `@font-face` fonts, all loaded before any
  island renders. Every spec names its fonts (`textStyle.fontFamily`,
  `config.font`, or per axis and mark in Vega). Nothing may fall back to a
  system font: the harness fails a fixture whose SVG names any family other
  than Noto Sans or Noto Sans JP.
- Time zone UTC, locale en-US. Only inline data, with no network.

## Pipeline

All commands run from the repo root. `npm ci` in `fixtures/tools` runs
automatically the first time.

| Command | What it does |
|---|---|
| `fixtures/tools/reference.sh <out>` | **Check** (what CI runs): renders every fixture in the pinned Chromium, rasterises at 96 dpi, and compares with the committed references. Exits 1 if a page or island changed. Writes `<out>/reference-report.json`, and per fixture `chrome.pdf`, `chrome-N.png`, `island-I.svg/.png`, `prepass.html` (markers replaced by Chrome's SVG) and `render.json`. |
| `fixtures/tools/reference.sh --update <out> [name...]` | Rewrites the committed references. Only for a new fixture, or a deliberate Chromium or library upgrade, said so in the pull request. Never to make surimono pass. |
| `fixtures/tools/compare.sh <fixture> <pdf> <out>` | Compares a surimono + fulgur PDF with the page references. |
| `fixtures/tools/compare.sh --island I [--printer chrome\|fulgur] <fixture> <svg> <out>` | Compares one island SVG from surimono with `island-I.png`. With `--printer chrome` (default) Chrome draws both sides, so the score measures surimono's SVG alone. With `--printer fulgur` it also includes fulgur's SVG printing. |
| `fixtures/tools/fulgur-baseline.sh <out>` | fulgur prints Chrome's own SVGs (`prepass.html` and each island alone). The score is the floor surimono + fulgur can reach. Needs `fulgur` 0.40.0 on PATH or `$FULGUR`. |
| `node fixtures/tools/calibrate.mjs --out <out>` | Scores known faults against the island references (how the threshold was chosen). |
| `node fixtures/tools/gen-islands.mjs [--check]` | Regenerates `input.html` and `meta.toml` from `tools/defs/islands.mjs` (seeded data, byte-identical on every run). |

Comparison output: `score.json`, and `side-by-side-N.png` with Chrome on the
left, the candidate in the middle, and the diff on the right. In the diff,
red marks near-mismatched pixels (they count), orange marks pixelmatch
differences, and yellow marks anti-aliasing only.

The Chrome side runs fully offline. Playwright serves `fixtures/` from a
made-up origin (`http://fixtures.surimono.test`) and aborts every other
request. It uses the full Chromium build in new headless mode (`channel:
"chromium"`), not the headless shell.

### Reproducing references in CI

`scripts/ci/reference.sh` calls `fixtures/tools/reference.sh "$CI_JOB_OUT"`.
With `$CI` set, it first runs `npm ci`, `npx playwright install --with-deps
--no-shell chromium` (the Chromium build that matches the pinned Playwright)
and installs poppler-utils if needed. Then it checks that `gen-islands.mjs`
still produces the committed inputs, and renders every fixture in check mode.

A fresh render reproduces a reference when its pixels are identical to the
committed PNG (`identical`), or when only anti-aliasing differs: same size, and
pixelmatch finds no non-anti-aliasing pixel (`reproduced`). Anything else is
`changed`. It fails the job and writes `check-<page|island>-N.png` side by side.
Locally (Ubuntu 24.04, poppler 24.02.0, Chromium 153.0.8010.12) two runs are
pixel-identical.

## Diff metric

**Score:** the share of near-mismatched ink in the worst 32×32 window. A pixel
matches when the other image has a pixel within 1 px whose R, G and B are each
within 128/255, checked in both directions. Only "ink" counts: pixels that are
not white in either image. The score is the largest share of mismatched ink in
any 32×32 window (stride 16; windows with fewer than 24 ink pixels are
skipped). **Pass: score ≤ 10%** and identical page sizes. pixelmatch 8.0.0
(threshold 0.1, anti-aliasing ignored) is also reported as `diff_ratio_ink` and
drawn in the diff image.

**Why not plain pixelmatch:** at 96 dpi most text pixels are anti-aliased
edges, and pixelmatch skips them. It scored "one label in four missing" at
0.5% but a harmless half-pixel text shift at 2 to 4%, so no threshold
separates the two. The 1 px / 128 tolerance absorbs sub-pixel glyph placement,
which differs between any two engines. Thin CJK strokes need the 128: with 96,
half-pixel shifts scored up to 16%. The window turns a local fault into a large
number instead of diluting it in a page of white space and bars.

Calibration: `calibrate.mjs` has Chrome print deliberately altered copies of
Chrome's own island SVG for all 10 fixtures, then scores them (worst window):

| Fault | Min | Max | Fails at 10% | Should |
|---|---|---|---|---|
| text shifted 0.5 px right | 0.0% | 0.0% | 0/10 | pass |
| text shifted 0.5 px down | 0.0% | 0.0% | 0/10 | pass |
| text shifted 1 px right | 0.0% | 0.0% | 0/10 | pass |
| letter-spacing +0.2 px (labels about 2% wider) | 0.0% | 24.0% | 4/10 | borderline |
| text shifted 3 px right | 18.5% | 57.1% | 10/10 | fail |
| one label in four missing | 31.1% | 67.9% | 10/10 | fail |
| whole chart scaled to 99% | 34.9% | 100.0% | 10/10 | fail |
| all text bold | 0.0% | 31.9% | 7/10 | fail |
| Latin text in Noto Sans JP instead of Noto Sans | 0.0% | 13.3% | 1/10 | fail (a no-op on the 4 all-Japanese fixtures) |

The metric catches what a measuring engine gets wrong: shifted, missing or
resized text and marks. It does not reliably catch a wrong font face or weight
when the metrics are close. Those are better checked in the SVG itself: every
`font-family` should name a registered font (P1-GFX-03). The Chrome harness
already fails any fixture whose SVG names a font outside `fixtures/fonts/`.

All 20 pass, so a surimono + fulgur failure means surimono's SVG differs from
Chrome's. Getting there took a page template that avoids five fulgur 0.40.0

border colours, fractional line heights, and Chrome's default
`text-spacing-trim`. The template uses whole-pixel sizes, fixed-basis flex rows
instead of `<table>`, and `text-spacing-trim: space-all`.

## Which comparison gates what

| Comparison | Measures | Gate |
|---|---|---|
| `compare.sh --island I` (Chrome prints surimono's SVG) | surimono's island SVG alone | ≤ 10%: the checkpoint-2 criterion |
| `compare.sh --island I --printer fulgur` | surimono's SVG plus fulgur's SVG printing | ≤ 10% (fulgur's own floor is ≤ 2.9%) |
| `compare.sh <fixture> <pdf>` (surimono + fulgur page) | the whole document | ≤ 10% (fulgur's own floor is ≤ 5.7%) |
